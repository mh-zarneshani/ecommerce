# Acceptance contract

Implement executable checks for these IDs. Expected values live here or in `qa/golden.json`; runtime code (including planners) must not import either. Compare results against a real import/event stream, not a constant or a snapshot generated by the implementation under test. Show `PASS`, `FAIL` or `NOT RUN` with command, expected, actual and concise evidence in `reports/acceptance.md`.

| ID | Setup → observable result |
|---|---|
| D1 | Import bundled XLSX at the specified cutoff. Compare all three workbook accounts (Digikala, Okala, Snapp) to the independent row, pack, target, spend and budget expectations in the golden file. Reconcile ratios from those totals, not summary percentages. Distinguish month attainment from pace to date; for بهمن day 15 elapsed target fraction is (8+7×1.4)/(23+7×1.4). |
| D2 | Reimport identical file, then in a test dataset submit identical record in a different batch, higher revision, older arrival and equal-revision conflict. Totals unchanged on replay/old; correction replaces exactly once; conflict visible, no double counting. Reimport plans without multiplying target. Zero/missing denominator is unknown, true zero numerator with known positive denominator is 0%. |
| X1 | Feed one normalized Digikala sale through a tiny offline test reader in an isolated dataset, replay it, then correct it. Query through the same services as workbook import: totals change once per distinct accepted revision, provenance is visible, no workbook/manual/demo totals change. No network, real credentials or changes to metrics, case rules or dashboard for a different reader. Verify the three accounts are selectable for workbook filters and manual entry, without a third synthetic case. |
| C1 | Start `class-demo.initial`. Exactly two open cases, correct scoped types, store, evidence and calculated percentages. First case and next action match the frozen expectation. Both accounts appear in one view. |
| C2 | From C1, edit and approve the first draft twice. One referral with edited text and original retained. Advance success branch: fresh same-store evidence attached, result visible, still not closed. Non-owner cannot close; owner closes. Restart the process/open persisted DB: timeline and owner survive. |
| C3 | Independently restore C1. Reject the pending proposal → zero referrals. Advance failure branch: investigation changes tools/action to verify source, case stays open, no inferred recovery. Replay same event; snapshot counts of cases, drafts, referrals, evidence links and events remain unchanged. Demo reset never touches workbook data. |
| C4 | Test cap equality, scope/time of an approved exception and competing equal-priority caps; stale observation at age >5 vs fresh at exactly 5; future/inaccessible witness, out-of-coverage and mismatched store. None can falsely open/resolve a case. An older orderable observation received late cannot undo a newer stockout; a genuinely new stockout after closure creates a new episode. |
| A1 | At least one trace actually chooses a different next read when the previous tool result changes for the same case. Reject unauthorized actions, missing/foreign/future citations and invalid output. With unavailable tool or exhausted budget, log why, keep open, request review. Exercise real adapter loop using simulated tool-call responses; label a live provider run `NOT RUN` if not available. |
| A2 | Run offline planner and fixed baseline on the same labeled `qa/golden.json` states. Fixed queue: order open stockouts before discounts, tie by case ID; static action by issue type, no dynamic verification. Give each the same accessible evidence. Report exact top-1 agreement when labeled, next-action agreement, supported evidence (right scope/time and supports the claim), and correct deferrals / insufficient-evidence states. Give numerators/denominators, no score for empty denominator. Report one observed action difference and witness, or no improvement. Do not use labels as planner input. |
| P1 | Run tests and smoke-start app on a fresh local DB; exercise both paths through UI or UI harness (report manual/untested steps). Confirm warm filter changes do not open XLSX. Time one initial import and median of at least 5 warm dashboard queries; include environment, selected rows, sample count. These are measurements, not an SLA. |
| H1 | In hosted config, verify anonymous sessions cannot read/use the app, invoke inference or reset; authenticated but unauthorized users cannot approve/close. With an intercepted fake transport, show no payer call on anonymous actions, workbook selections, duplicate events or rerenders, no workbook data or secrets in requests/logs/UI, and a persistent daily budget that stops calls when exhausted. Exercise 401/402/429 and timeout; verify visible deferral, no hidden offline substitution, no state closure or referral. No real key needed. |
| H2 | Opt-in VPS smoke: open the actual HTTPS domain, verify login and no public access to the app port; on one synthetic case observe a real provider tool call, scoped return and validated Persian draft + witness, no auto-referral. Replay without a second charge. Confirm DB persists after service restart and restore a backup into a separate test DB. Report provider/model, counts, time and result without secrets. Mark any unexecuted steps `NOT RUN`, never count a mock as a live pass. |

Definition of done: runnable app + README per spec + real report. A passing unit test is not proof of a manual UI path or a model run. Report scope and remaining blockers accurately.
